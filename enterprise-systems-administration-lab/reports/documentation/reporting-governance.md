# IT Reporting Governance

## Standards

- Every report must identify audience, owner, source data, refresh cadence, and purpose.
- Metrics must be defined consistently.
- Sample data must be clearly labeled as sample data.
- Sensitive user, system, or security information must be redacted.
- Executive reports should focus on impact, risk, and required decisions.
- Technical reports should include evidence and remediation details.
- Reports must preserve source timestamps and time zones.
- Exceptions require owner, business justification, control, and expiration date.

## Review Cadence

| Report | Cadence |
|---|---|
| Executive Operations | Monthly |
| Infrastructure Health | Weekly |
| Patch Compliance | Weekly |
| Security Summary | Weekly |
| Backup Status | Daily and Monthly |
| Capacity Forecast | Monthly |
| SLA Performance | Monthly |
| Incident Metrics | Monthly |
| PKI Expiration | Weekly |
