# Portfolio Evidence Guide

**Owner:** Jamie Christian  
**Version:** 2.0

## Positioning statement
This is a simulated enterprise lab built to demonstrate repeatable IT operations work. It does not represent production employment, but the procedures, artifacts, and controls are structured to mirror real service-management and infrastructure practices.

## Best recruiter review path
1. Read `executive-overview.md` for the business problem.
2. Review the architecture and environment baseline.
3. Open one implementation artifact, preferably AD, Intune, or Terraform.
4. Review one completed operational checklist.
5. Review one incident and one change record.
6. Review one troubleshooting scenario with validation evidence.
7. Review the KPI or service-level report.

## Evidence set to feature
- Hybrid architecture diagram
- AD user and group administration record
- Group Policy validation output
- Windows or Linux health-check output
- Intune compliance evidence
- Terraform configuration and plan output
- CloudWatch alarm test
- Backup and restore validation
- Resolved incident record
- Approved change record
- Knowledge article or known-error record

## Interview demonstration
### Situation
A hybrid environment required reliable identity, endpoint, server, and AWS operations.

### Task
Design a supportable environment and create the procedures needed to operate it after deployment.

### Action
Standardized naming and baselines, implemented identity and cloud services, configured monitoring and backup, created incident and change processes, and wrote scenario-based runbooks.

### Result
Produced a traceable portfolio in which technical claims are linked to operational evidence, acceptance criteria, and repeatable procedures.

## Strong interview talking points
- Why DNS health is essential to Active Directory.
- Why group-based access is safer than direct permissions.
- How a pilot ring reduces endpoint policy risk.
- How to distinguish host health from application health.
- Why backup success is incomplete without restore testing.
- How incident, problem, and change records connect.
- Why Terraform improves repeatability and reviewability.

## Integrity guidance
- Never describe the lab as a real employer production environment.
- Never invent user counts, uptime, ticket volume, or business results.
- Clearly label simulated metrics.
- Use evidence to demonstrate process and technical skill.
